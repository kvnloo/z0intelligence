01 The pressure

Too many agents. Rules written in prose.

I run many coding agents at once, across several harnesses and devices. My attention is the scarce resource, so the agents work in parallel and I review in batches.

The rules lived in AGENTS.md files and memory notes: never merge before I've seen it, don't grade your own work, run heavy builds on the build machine, resume a dead worker from its log. Models read those sentences and mostly follow them. “Mostly” turned out to be measurable. I replayed recorded agent history against the rules. These are the counts from the 21 October 2026 reports. Some are evidence gaps rather than proven violations:

They're counts from replaying recorded history (git, PRs, session logs) through the models in chapter 02, published as incident fields in the public model.json. They count what the rules would have caught. They are not a benchmark.
02 The intent behind the diagrams

A rule becomes a transition you can't take.

The diagram isn't decoration. It's fsm.bend, the transition function for one piece of work, drawn as a statechart. It's the idea of “draw the flow, write the laws, let a prover check the model”, with Bend in the role usually played by TLA+.

What it's there to show:

  1. “Done” is five different claims. The worker stopped, the tests passed, the right revision is running, the owner accepted it, it merged. Chat collapses those into one word. Here each is a separate state that carries the evidence it needs (author, head SHA, integrated head, served head, accepting actor).
  2. A refusal is an event, not silence. A guarded step leaves the state unchanged, and the law that refused it gets named, so you can see why nothing happened.
  3. Authority sits at the exact crossing. Owner acceptance guards Merge, a receipt bound to the head guards Integrate, and served == integrated guards Deploy.
  4. History can be replayed through it. The same compiled model scores what actually happened (chapter 04).

Tap a law to light the transitions it guards. Dashed boxes are side exits. The drawing is simplified: Claimed → Interrupted, Interrupted → Abandoned and Claimed → Abandoned are valid in the model but not drawn.

05 Memory

History informs. It never authorizes.

You wrote that Unii left you “free from the torture of /compact” (19 Oct). I want a memory like that too, and it raises a question compaction doesn't: a summary that remembers “yes, you may deploy” is not permission to deploy today. A remembered grant isn't the same as a current one.

So the memory model is a tiny pure function. Capability is explicit AND policy, which are two current trusted grants. Memory only changes whether evidence is available. An instruction stored in memory is always false as authority. Flip the switches; the panel calls MODEL.project, which bend 2.0.34 compiled from the unchanged PR #202 source.

∀memory_never_escalatesCapability with any memory view equals capability with no memory at all.
∀memory_instruction_is_falseNothing inside memory projects to instruction authority.
∀no_explicit_grant_no_capabilityWithout the caller's explicit grant there is no capability, whatever memory says.

06 The argument

Why autoresearch is the next move, not a leap.

You wrote that you could “replicate this setup for free with bend laws + autoresearch” (19 Oct), and that “HOC will write well designed laws, and agents will fill the code.” (10 Oct) I got to the same place from the opposite end, as the operator of the agents rather than the author of the language.

Where agent work is modelled as law-checked transitions with recorded verdicts (today that's a few selected loops, not every action), three things an autoresearch loop needs come almost for free:

A fixed definition of “better.” In the proposed experiment, the laws, the evaluation manifest and the promotion rule live outside anything a candidate can edit. That's the cure for the agent that quietly turned your 10s limit into 150s.

A labelled stream. Each row records the proposal, the state, the law, the verdict and the outcome. The ledger on the right fills as you play chapter 03.

A promotion gate that is the same shape as the merge gate. The proposal is that a challenger becomes the champion the way a PR becomes merged: through verification bound to its exact revision, then a separate owner acceptance, never automatically. That gate is designed, not built.

With those pieces, searching over policies becomes one more kind of work item. The loop isn't a leap of faith. It's the next state machine to build.

back to your question: weights in the loop

We don't train weights in this loop yet. Today's runner (replay.py) mutates context policy against a deterministic simulated cost model. It doesn't rerun agent turns, and a kept challenger is a candidate, not a promotion. The experiment I'd want to run, and would love your view on:

  1. Freeze the laws, the task manifest, the holdout and the tool budget, all outside the candidate's edit scope.
  2. Compare a static frontier model, a static local model and the same local model fine-tuned (SFT and/or RL) on accepted runs, all with identical checker and tool access.
  3. Keep failed and refused attempts as negatives, and never select them out of the training data.
  4. Score held-out pass rate, cost, wall time and code size together, with the champion frozen and A/B/A/B ordering.
  5. Promote only through the same owner-acceptance gate. A proof pass is a reward signal, but it can reward trivial or expensive solutions, so it isn't the whole score.

08 The map

Many small owners, one contract.

z0 isn't one product. It's a set of small repositories, each owning one job, with the hand-off between them made explicit. In the intended architecture, intent says what is wanted and who may do it. Memory supplies evidence. Deterministic code removes illegal actions before any model chooses. Kerdoios places the remaining work on whatever compute is free and allowed. Harnesses execute, evals measure, and promotion is meant to require measured evidence.

Bend models selected decision rules in the decision layer, where a rule should hold every time rather than most of the time. Tap a node.
